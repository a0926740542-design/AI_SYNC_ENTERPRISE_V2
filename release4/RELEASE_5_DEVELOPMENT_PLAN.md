# AI_SYNC Enterprise V3.005-A — Release 5 開發計畫

> 狀態：DEV / 未正式發布。基線：已發布的 Git Tag `v3.005-a-r4.1`。此文件是開發計畫，不代表功能已完成。

## R5 目標與驗收順序

### R5.1 — 寫入穩定與大型 DWG 保護（優先）
- 避免複製正在持續寫入的來源檔案：連續觀察大小、mtime、檔案識別等穩定性；必要時採取檔案可讀性與重試策略。
- 針對複製期間來源再度改變的情況，檢查來源前後狀態；不將不穩定的暫存內容替換正式 BACKUP。
- 需處理 Windows/AutoCAD 常見檔案鎖、暫存檔與重試；保留 R4.1 互斥保護。
- 驗收：慢速寫入大型測試檔時不發布部分備份；寫入結束後最終 SOURCE/BACKUP 一致；VERSION 不重複。

### R5.2 — 異常復原
- 啟動掃描與補同步：處理程式關閉期間的新增及修改。
- 中斷後殘留暫存檔安全清理；錯誤與重試記錄。
- 驗收：模擬強制停止、重新啟動、重新掃描；無資料損毀及非預期重複 VERSION。

### R5.3 — 筆電到家中電腦傳輸
- 先明確決定目的端路徑與網路連線方式（如 VPN + SMB 或其他受驗證通道）。
- 支援連線中斷、恢復、重試及稽核紀錄；不假設目的端永久可用。
- 驗收：實際兩台 Windows 電腦、斷線重連及多層資料夾測試。

### R5.4 — 正式部署驗收
- pytest、自動化壓力測試、AutoCAD DWG 實機測試、記錄及回復演練。
- R5 測試環境和 R4.1 正式版分開，不直接覆蓋 R4.1。
- 驗收後才建立 R5 Git Tag 與正式 GitHub Release。

## 技術基線（已檢視 R4.1）
- `release4/app/main.py`：單一執行個體鎖。
- `release4/app/file_copier.py`：來源複製到暫存檔、比較、VERSION 保存及 `os.replace`，含跨程序目的檔鎖。
- `release4/app/core/sync_engine.py`：watchdog 事件、路由、工作者、複製器。
- `release4/config/config.json`：目前仍是 `C:\\AI_SYNC_TEST` 測試路徑。
- **已知缺口**：R4.1 複製流程沒有明確檢查「來源檔案在複製前後是否仍在變更」；R5.1 應先補上這一層保障。

## 安全與相容性
- 不在開發期間直接修改正式 R4.1 Tag 或 Release。
- 不在未驗證前將來源設定切到真正的工程工作資料夾。
- 保持 Windows Python 3.14 的測試相容性。
